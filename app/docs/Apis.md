# ClipScope keyword-search API

The backend exposes these workflow routes in addition to the provider cURL examples in this document:

| Method | Route | Purpose |
| --- | --- | --- |
| `POST` | `/api/v1/search-jobs` | Validate criteria and queue a keyword discovery job. |
| `GET` | `/api/v1/search-jobs` | List persisted jobs (`page`, `page_size`, optional `status`). |
| `GET` | `/api/v1/overview` | Return persisted dashboard metrics and recent failures. |
| `GET` | `/api/v1/search-jobs/{job_id}/progress` | Return status and collection/filter counters. |
| `GET` | `/api/v1/search-jobs/{job_id}/videos` | Paginate, sort, and search results. `decision=all|matched|unverified|rejected` selects the decision view; the default is all stored decisions. |
| `GET` | `/api/v1/videos/{video_id}` | Return normalized video fields, category/language evidence and confidence, first/last-seen timestamps, and collection provenance. |
| `GET` | `/api/v1/search-jobs/{job_id}/videos/export` | Download the selected results as JSON (default) or CSV using `output_format`; supports the same `decision` and `search` filters. |

Create request fields are `keyword` (required), `category`, `min_views`, `max_views`, `min_age_days`, `target_language`, `language_requirement` (`spoken` or `text`), and `target_count`. The provider request uses the exact keyword discovery example below and leaves its `country` blank; the product has not defined country semantics. A target count is not a reason to weaken criteria.

The confirmed `/datasets/v3/scrape` response was HTTP 202 with `snapshot_id`; it did not contain video records. The backend follows the documented Bright Data progress and snapshot retrieval endpoints. An empty successful provider snapshot completes with zero matches and an explicit target shortfall. See `backend/README.md` for database setup and the full lifecycle.

The backend reads `BRIGHTDATA_API_TOKEN` and `MYSQL_PASSWORD` from its process environment and does not load `.env` files. `GET /api/brightdata/config` reports `token_configured: false` when the provider token is absent. Restart the backend after setting either secret; never send a token from the browser.
